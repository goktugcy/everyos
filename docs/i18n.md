# Internationalization

Turkish (`tr`) is the source locale (`LocaleMessages` type) and English (`en`) is the product
default and fallback. The complete supported set is Turkish, English, German (`de`), Spanish (`es`),
French (`fr`), Italian (`it`), Japanese (`ja`), Korean (`ko`), Russian (`ru`) and Simplified Chinese
(`zh`). `packages/shared/src/locale.ts` owns the identifiers.

## Resource boundaries

Add UI strings to `packages/i18n/src/locales/tr.ts` and every other locale. Components use i18next
keys, never literal UI text. Keep interpolation names, literal configuration keys, commands, paths
and protocol names intact. Translate the meaning of conditions and security warnings in full.
Distinguish an account password, a backup passphrase and the server's secret encryption key.

Server code imports `@everyos/i18n`. Browser runtime code imports `@everyos/i18n/client`, which
bundles English and loads every other language separately. `tags.ts` owns Intl region mappings.
The server also renders external notifications using the configured channel language. In
Settings › Account, choosing a language other than Turkish or English shows a brief notice above
the language selector that translations may contain errors and feedback is welcome.

The browser remembers successful selections in `everyos.locale`; a signed-in account's saved
language wins. With no selection on the device, the first supported language in the browser's
language list is used (`negotiateLocale`), and English when none is supported. A slow earlier
download cannot replace the latest selection. Failed downloads keep the current resource and allow a
later retry. Japanese, Korean and Chinese have language-specific system font fallbacks.

## Plural forms and validation

Locale files implement `LocaleMessages`. Keep all Turkish source keys, including `_one` and
`_other`, and add the categories required by `Intl.PluralRules` for the locale. Russian also needs
`_few` and `_many`; Spanish, French and Italian need `_many`. Every category retains the source
interpolation variables, including `{{count}}` for singular forms that also represent 21 or 31.

Run `pnpm check`, then `pnpm build && pnpm test:e2e`. The translation tests check completeness,
empty strings, placeholder parity, plural categories, language names and dynamic loaders. The
language end-to-end tests switch every sign-in language, reload the saved choice, and save every
supported account locale through the real API before reopening the desktop.

Automated checks establish structural correctness, not native fluency. Review translations in
context, especially data-loss warnings, permissions, encryption terms, regional conventions and
text clipping. Do not treat a passing test as proof of linguistic accuracy.
